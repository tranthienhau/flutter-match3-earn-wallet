# Screenshot capture flow

The screenshots in `screenshots/` are real captures from the running app on an
iOS Simulator, driven by `integration_test`. To regenerate them:

```bash
# 1. Boot the simulator first (driver attaches to a running device)
xcrun simctl boot "iPhone 17 Pro"

# 2. Deps
flutter pub get

# 3. Drive the app and write PNGs to screenshots/
flutter drive \
  --driver test_driver/integration_test.dart \
  --target integration_test/screenshot_test.dart \
  -d "iPhone 17 Pro"
```

## How it works

- `test_driver/integration_test.dart` uses `integrationDriver(onScreenshot:)` to
  write each captured PNG to `screenshots/<name>.png`.
- `integration_test/screenshot_test.dart` boots the full app inside a
  `ProviderScope`, then navigates the five tabs and drives a complete economy
  loop: clear a Memory Match board (deterministic seed 42), mature the Net-30
  queue, cash out via OPay, verify an offerwall S2S postback, and toggle the
  anti-fraud gate. Each key screen calls
  `binding.convertFlutterSurfaceToImage()` + `binding.takeScreenshot('NN-name')`.
- Screens with one-shot timers (hint reveal, flip-back, S2S postback) use fixed
  `pump(Duration)` rather than `pumpAndSettle` so capture is deterministic.

## Demo GIF + flow diagram

```bash
# demo.gif - cycle the 8 PNGs (ffmpeg, palette for quality)
i=1; mkdir -p /tmp/m3f
for f in 01-home 02-game 03-win 04-wallet 05-payout 06-earn 07-trust 08-trust-blocked; do
  cp screenshots/$f.png /tmp/m3f/$(printf '%02d' $i).png; i=$((i+1)); done
ffmpeg -y -framerate 0.66 -i /tmp/m3f/%02d.png \
  -vf "scale=320:-1:flags=lanczos,palettegen=stats_mode=diff" /tmp/pal.png
ffmpeg -y -framerate 0.66 -i /tmp/m3f/%02d.png -i /tmp/pal.png \
  -lavfi "scale=320:-1:flags=lanczos[x];[x][1:v]paletteuse=dither=bayer" \
  -loop 0 screenshots/demo.gif
```

`screenshots/flow-diagram.png` is generated by a PIL script that draws the
revenue/payout boxes-and-arrows shown in the README.
